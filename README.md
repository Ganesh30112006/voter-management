# Voter Desk — Voting Management System (frontend)

React + TypeScript + Vite frontend for managing administrators, wards, booths, voters and donation distribution.

- **Super Admin** manages everything: administrators, wards & booths, voters, imports, settings, audit logs.
- **BL Admin** views all voters, has a *My Ward Voters* tab for their assigned wards, records donations for any voter, and sees donation history and reports.

The core workflow: open a voter → **Donate** → enter the receiver's name and mobile (amount is prefilled) → confirm.
The server records the transaction ID, timestamp and admin, and the voter shows a green **✓ Received** tick in place of the Donate button.

## Requirements

- Node.js 18+ (tested on Node 24)
- npm 9+

## Install and run

```bash
npm install
npm run dev          # http://localhost:5173 using the in-browser mock backend
```

## Environment variables

| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Base URL of the REST backend (e.g. `https://api.example.org/api`) |
| `VITE_USE_MOCK` | `true` uses the in-browser mock backend. **Must be `false` in production**; the app refuses to start otherwise |
| `VITE_MOCK_PASSWORD` | Password for seeded mock admins (mock mode only) |

`.env.development` turns the mock on; `.env.production` turns it off. When the mock is off, its code is not included in the production bundle.

## Backend contract

Every service in `src/services` calls one REST endpoint. The mock in `src/mocks/mockServer.ts` implements the same rules a real backend **must enforce independently**:

- **Auth:** `POST /auth/login {mobile, password, remember}` → `{token, admin, expiresAt}`. Bearer token on every request. Any `401` signs the user out with a "session expired" message.
- **Admin IDs:** sequential `BL-1, BL-2, …`, generated by the server. Admin mobile numbers are unique. The Super Admin sets the initial password (`POST /admins`) and can change it (`PUT /admins/:id/password`); doing so revokes that admin's sessions.
- **Donations:** `POST /donations {voterRecordId, amount, receiverName, receiverMobile, idempotencyKey}`, plus an `Idempotency-Key` header. The server sets the ID, timestamp and admin, rejects a second successful donation for the same voter (`409`), returns the original transaction for a retried key, and enforces the configured amount when amount changes are disabled.
- **Cancellation:** `POST /donations/:id/cancel {kind: 'Cancelled'|'Reversed', reason}` (Super Admin). Cancelled or reversed transactions never count as received.
- **Access:** BL Admins get `403` on administrator, ward, voter-edit, import, settings and audit endpoints.
- **Validation errors:** `400`/`409` with `{message, fieldErrors: {field: message}}`; the forms show these next to the field.
- **Reports:** unique-voter counts are computed separately from transaction counts.

## Import format

Accepted files: `.xlsx`, `.xls`, `.csv` (max 10 MB; the file signature is checked, so a renamed PDF is rejected). Download the template from the Import page. Column order and headings may vary, and you map them in the UI. Status must be **Active**, **Not Active** or **Shifted**; case and spacing are normalized, and a missing or unknown status is flagged, never defaulted. Rows are uploaded in batches of 100.
